System Settings

Three pages under Settings change how ShuleNova behaves for the whole school: Global Settings (choices such as how averages are worked out and when idle users are signed out), Approval Workflows (who approves what) and Licence.

Global Settings

Settings > Global Settings groups the settings into sections. Click a section's bar to open it (one opens at a time). Each setting has a short description beside it.

Changing settings

  1. Open a section and change the values you need. A changed setting is highlighted, its section shows "n changed", and the bar at the top counts the unsaved changes.
  2. You can change settings in several sections before saving.
  3. Click Save changes at the top and confirm. Only the settings you changed are saved.

If you leave the page without saving, the changes are lost. The bar says All settings are saved when nothing is waiting.

The sections

Only the sections for the modules your licence includes are shown.

SectionWhat it sets
General Dashboard SettingsHow many to-do items and upcoming events the dashboard shows; whether it names the top student; the exam type the dashboard's class performance card shows; how class averages are worked out (only learners who sat the exam, or every learner allocated, absentees counting as 0); whether a reason is required for every absence in student and staff attendance; the prefixes for department codes and budget plan codes; and the Approval Edit Lock Policy (below).
Finance SettingsThe accounting period (termly or yearly), how payments are spread over invoice items, automatic journal posting, the payroll journal, and the default accounts (debtors, cash, PAYE and the rest). See the Finance chapter.
Payroll SettingsThe school's KRA PIN for payslips, and how net pay is rounded. See the Payroll chapter.
Communications SettingsWhere parents' phone numbers and emails for messages come from: the parent record, the learner record, or the parent and then the learner. See the Communications chapter.
Teaching Management SettingsWhen schemes of work and lesson plans fall due, for the tracker's "overdue" marking.
Grading System SettingsThe 4-point or 8-point grading for exams, assessments, values and co-curricular scores; ranking; how totals and means are worked out; broadsheet columns; and per-level overrides. See the Academics Set-up chapter.
Report Form SettingsWhat the report form shows: marks or grades, the values, co-curricular, responsibilities and community service sections, position, term dates and the title wording.
Elections SettingsThe defaults for new elections: the voter register (frozen or live), how often the results screen refreshes, and the order of names on the ballot.
Security SettingsIdle sign-out, the warning before it, and whether the user guides are shown (below).

Approval Edit Lock Policy

Under General Dashboard Settings, this decides when a record sent for approval (an expense, a budget, a scheme of work…) stops being editable:

  • Strict: locked as soon as it is submitted.
  • Lenient: still editable until the first approval step is approved.

An approved record is always locked.

Security settings

Approval Workflows

Some records need approving before they count: an expense before it is paid, a scheme of work before it is used. An approval workflow sets the steps a kind of record goes through and the role that approves each step. Settings > Approval Workflows has the form on the left and the workflows already set up on the right.

How approval works

  1. The workflow says, for each step, which role approves it (for example step 1 Reviewer: Accounts, step 2 Approver: HeadTeacher).
  2. When someone submits a record, they choose a person for each step from the users holding that step's role. If only one user holds the role, that person is picked for them.
  3. Each approver finds the request under the bell at the top of the page, and approves it, rejects it or returns it with a comment. When the last step (marked Final) approves, the record is approved and locked.

So for approval to work, the step's role must be given to the right people on the Users page.

The forms that can have a workflow

FormWhat is approved
Budget, Budget AmendmentA budget plan, and later changes to it.
Expense RequestAn expense, before it is paid.
Journal Entry, Credit / Debit NoteManual journal entries, and credit and debit notes.
PayrollA processed payroll, before it is locked and posted.
Scheme of WorkA teacher's scheme of work for a subject and class, once a term.
Lesson Plans (weekly)A week's lesson plans for one subject and class.

A form can have only one Active workflow at a time.

Changing a workflow

  1. Click the pencil on the workflow in the list. Its details open in the form on the left (Edit Workflow).
  2. Change the Name or Description if needed.
  3. For each step, set the Step Name (Reviewer, Approver, Head of Department…) and the Role that approves it. Use Add Step for another step, the arrows to change the order and the bin to remove one. The last step is always the Final one.
  4. Tick who is told at each step: Notify next (the next approver), Notify previous (the approver before) and Notify applicant (the person who submitted it).
  5. Leave Maker-checker (prevent self approval) ticked so that nobody can name themselves as an approver of their own request.
  6. Click Update. Cancel Edit leaves without saving.

To create a workflow for a form that has none, fill in the same form without clicking a pencil first, choose the Form, and click Create.

Changes apply to new requests. Requests already submitted keep the approvers chosen when they were sent. A request that has been approved can be reversed only by a SuperAdministrator.

The Licence

Settings > Licence shows the school's licence on the left and the place to install a new key on the right.

Reading the licence

  • Licensed to, Licence (its number), Site (the web address it is for, or Any), Issued and Valid until, with the days left.
  • Modules: Core is always included. Each paid module shows On, Not licensed, or Licence not valid (it is in the licence, but the licence is not valid on this site or has run out).
  • The badge at the top right gives the licence's state:
StateMeaning
ActiveAll is well.
Expiring soonFewer than 30 days left. Contact Kodetek to renew.
Expired - grace periodThe licence has run out, but the modules keep working for 14 more days. The page says the date they stop.
ExpiredThe grace period is over. Only the core features work until a new key is installed. No data is lost.
Invalid keyThe key is damaged, usually not copied in full.
For another siteThe key was issued for a different web address.
Not installedNo key yet: only the core features are available.

When the state is anything but Active, a key icon with a short warning (such as Licence expiring) shows in every administrator's top bar; click it to open this page.

Installing a new key

To renew, or to add a module, contact Kodetek. They send a licence key: a long piece of text starting with SNL1.

  1. Copy the whole key from Kodetek's message.
  2. Paste it into the Install a licence key box.
  3. Click Install.

The key is checked before it replaces the current one: a key that is damaged, for another site or already expired is refused with the reason, and the old licence stays. A good key takes effect at once; the page reloads and the menus show the modules it includes. Only Administrators and SuperAdministrators can install a key.

Keep the key private. Treat the key like a password: do not post it in group chats or share it with other schools. Kodetek can always send it again.
